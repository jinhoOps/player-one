## 1. 정보 구조

핵심 아이디어: **의상 사이즈를 장비 슬롯에 붙인다.** 사이즈는 따로 노는 표가 아니라 "이 슬롯에 맞는 장비 규격"이다.

| 섹션 | 항목 | 게임식 표현 | 기본 공개 범위 |
|---|---|---|---|
| 프로필 | 닉네임, 칭호, 만 나이 | 캐릭터명 / Title / Lv. | 공개 |
| 클래스 | 직업군 + 실제 직업명 | Class / Subclass | 클래스 공개, 직업명 비공개 |
| 체형 | 성별 체형 (여성/남성) | 캐릭터 실루엣 | 비공개 |
| 외형 | 헤어스타일 (숏컷·단발·긴 머리·포니테일·똥머리) | 캐릭터 외형 | 항상 공개 |
| 신체 | 키, 몸무게, 골격근량, (체지방률) | Base Stats | 비공개 |
| 장비 | 투구 = 머리둘레/모자, 상의 = 상의 사이즈, 하의 = 허리둘레·하의 사이즈, 신발 = mm | Equipment Slots | 슬롯 외형 공개, 수치 비공개 |
| 자산 | 구간 | Wealth Tier | 비공개 |
| 인벤토리 | 오래 쓰려고 산 물건 (모델명·구매일·가격·구매처·수량·다시 살까·후기) | Inventory / 진열장 | 비공개, 진열한 것만 공개 |

| 클래스 | 직업군 | 컨셉 |
|---|---|---|
| 전사 | 현장·제조·운동·영업 | 몸으로 돌파 |
| 마법사 | 개발·연구·데이터 | 지식으로 세계를 조작 |
| 탱커 | 공공·관리·CS·운영 | 버티고 지킴 |
| 힐러 | 의료·돌봄·교육 | 남을 회복시킴 |
| 레인저 | 디자인·기획·마케팅 | 원거리 정밀 타격 |
| 상인 | 자영업·금융·사업 | 자원 순환 |
| 음유시인 | 크리에이터·예술 | 버프와 영향력 |

### 인벤토리

오래 쓰려고 산 물건을 기록해 두고, 나중에 찾아보고, 다시 사거나 수량을 채울 때 본다. 옷은 성격이 달라서 따로 "옷장"으로 설계한다(보류).

| 대분류 | 키 | 예시 |
|---|---|---|
| 디지털 | `digital` | 노트북·태블릿·폰·모니터·키보드·마우스·이어폰·충전기 |
| 카메라 | `camera` | 바디·렌즈·삼각대·액션캠·드론·조명 |
| 가방·잡화 | `bag` | 백팩·토트·지갑·시계·안경·벨트·우산·부티크 |
| 주방 | `kitchen` | 팬·웍·냄비·칼·도마·식기·텀블러·주방가전 |
| 리빙·가전 | `living` | 청소기·공기청정기·가습기·조명·침구·수건·가구 |
| 취미·레저 | `hobby` | 게임기·악기·캠핑·자전거·운동기구·피규어·문구 |
| 뷰티·케어 | `care` | 드라이기·면도기·향수·전동칫솔 |
| 직접 | `custom` | 이름을 직접 붙인 분류. 이름은 나만 본다 |

- 다시 사기에 필요한 것 위주: 모델명(품번), 구매처 링크, "다시 살까"(같은 걸로 / 다른 걸로 / 안 삼), 한 줄 후기
- 수량형: 수건·식기처럼 개수를 채워 두는 물건만 보유/적정 수량을 적는다. 보유 < 적정이면 "보충" 배지
- 처분한 물건도 지우지 않고 흐리게 남긴다(다음 구매 때 참고)

### 자산 티어

- 1억 미만: 천만 원 단위 10구간
- 1억 이상: 억 단위 구간
- **정확한 금액은 저장하지 않고 구간 인덱스만 저장한다.** 유출 시 피해를 최소화하기 위함.

| 레어리티 | 구간 |
|---|---|
| Common | 3천만 원 미만 |
| Uncommon | 3천만 ~ 1억 |
| Rare | 1억 ~ 5억 |
| Epic | 5억 ~ 10억 |
| Legendary | 10억 이상 |

## 2. 프라이버시 모델

### 필드 단위 공개 설정

Supabase RLS는 행 단위라 필드별 공개 설정을 직접 걸 수 없다.

- 모든 프로필 데이터는 **본인만 읽을 수 있는 테이블**에 둔다 (RLS: `auth.uid() = user_id`).
- 같은 행에 필드별 공개 여부 맵 `visibility jsonb`를 저장한다.
- 타인 조회는 `get_public_profile(handle)` — `SECURITY DEFINER` RPC가 `visibility`를 보고 공개 필드만 골라 반환한다. 테이블 자체는 anon에 노출하지 않는다.

### 핸들

- 핸들이 없으면 `/me` 이름 카드 아래 "공개 주소 정하기" 카드(`HandleClaim`)가 뜬다. 로그인 계정 아이디(이메일 앞부분)를 핸들 규칙에 맞춰 미리 채우고, 이미 쓰는 이름이면 `_2`, `_3`…을 붙인다.
- 구글 계정 아이디는 곧 이메일 주소라서 자동으로 공개하지 않는다. 본인이 "이 주소로 공개"를 눌러야 저장되고, 계정 아이디 그대로면 그 점을 알려준다.
- 핸들은 "프로필 편집"에서 바꿀 수 있다. 바꾸면 이전 주소(`/p?u=이전핸들`)는 열리지 않는다고 미리 알려주고, 비우면 공개 프로필이 닫힌다.

### 닉네임 변경 제한

- 일주일(최근 7일)에 3번, 그리고 3분에 한 번까지. 처음 정하는 닉네임은 횟수에 넣지 않는다.
- DB 트리거(`limit_nickname_changes`)가 막는다. 변경 기록 `nickname_changes`는 서버만 쓰고, 클라이언트가 보낸 값은 무시한다.
- 편집 폼은 남은 횟수와 다음에 바꿀 수 있는 시각을 보여주고, 닉네임이 바뀐 경우에만 보낸다.

### 탈퇴

- 설정 모달 → 맨 아래 "위험 구역"의 "회원 탈퇴". 누르면 그 자리에 확인칸이 펼쳐지고, 핸들(없으면 "탈퇴")을 그대로 입력해야 탈퇴 버튼이 열린다. 위험 구역만 `--danger` 색을 쓴다.
- `delete_my_account()` RPC(`SECURITY DEFINER`, 로그인한 사용자만)가 `auth.users`의 본인 행을 지우고, `profiles`·`items`는 cascade로 함께 지워진다.

### 3D 모델을 통한 누설

몸무게·골격근량으로 체형 morph를 만들면, 수치를 가려도 실루엣으로 드러난다.

- 신체 스탯이 비공개면 **타인 뷰에서는 해당 축이 평균 체형**으로 나온다. 체형(성별)이 비공개면 중성 마네킹이다.
- 비공개 값은 RPC 응답 단계에서 이미 빠져 있다. 클라이언트는 받은 공개 값으로만 morph를 계산하므로 비공개 morph 파라미터가 섞일 수 없다.
- morph 축(`src/lib/morph.ts`)은 한국 20–30대 평균 대비 −1…1이다. 키는 cm, 몸무게는 BMI, 골격근량은 체중 대비 비율로 본다.
- 헤어스타일은 외형이라 항상 공개한다. 비워 두면 체형별 기본값(여성 단발, 그 외 숏컷)을 쓴다.

### 인벤토리와 진열장

- `items`도 본인만 읽고 쓰는 테이블이다. 모든 아이템은 기본 비공개다.
- 아이템마다 "진열"을 켤 수 있고, 진열장은 6칸이다(DB 트리거로도 막는다).
- 타인은 `get_public_trophies(handle)`로 진열한 아이템의 **분류·이름·브랜드·구매 연도만** 받는다. 가격·구매처·모델명·후기·수량은 진열해도 나가지 않는다.
- 직접 만든 분류는 이름 없이 `custom`으로만 나간다.

## 3. 라우팅과 인증

| 경로 | 내용 |
|---|---|
| `/` | 랜딩: 큰 워드마크(Player One) + 캐릭터 미리보기 + Google 로그인 + 특징 카드 3개 |
| `/me` | 내 캐릭터 시트, 인라인 편집, 진열장 미리보기 |
| `/me/items` | 인벤토리: 아이콘 그리드, 분류·검색·필터, 아이템 편집 |
| `/p?u=<handle>` | 공개 뷰 + 진열장 |
| `/village` | 마을: 접속 중인 플레이어, 말풍선 채팅 (핸들 필요) |
| `/settings` | 설정 모달을 연 채로 `/me`로 보낸다(옛 링크용). 설정은 상단 바 "설정"으로 어느 화면에서나 모달로 연다 |

- 정적 export(`output: 'export'`)에서는 `/p/[handle]` 같은 동적 경로를 빌드 시점에 만들 수 없다. 공개 프로필은 `/p?u=handle` 형태로 **클라이언트에서 fetch**한다.
- Google 로그인은 PKCE 콜백 페이지를 클라이언트에서 처리한다.

## 4. 레이아웃

### 데스크톱

16:9 한 화면 구도.

- 왼쪽: 3D 스테이지 (넓게). 왼쪽 안쪽에 장비 레일(아이콘 4개, 머리 → 신발)
- 오른쪽: 정보 패널 (폭 1000px 이상: 화면의 46%, 560–720px, 이름 카드 아래 카드 2열 — 스탯·장비 / 클래스·자산·진열장. 그보다 좁으면 360–440px 1열. 넘치면 패널 안에서만 스크롤)
- 슬롯 hover → 3D 모델의 해당 부위가 빛나고, 슬롯과 부위 사이에 점선이 그려진다

### 모바일

- 상단: 화면 폭 3D 스테이지(52vh), 그 아래 장비 슬롯 4개가 한 줄
- 하단: 탭 (스탯 / 장비 / 클래스·자산). 장비 팝오버는 하단 시트
- 아래로 스크롤하면 위에 고정된 스테이지가 52vh → 28vh로 줄어들며 패널이 올라온다

### 공통

- 캐릭터와 슬롯 열은 한 화면 높이로 고정(sticky)되어, 오른쪽 패널을 스크롤해도 캐릭터 전체가 보인다.

## 6. 컴포넌트

### CharacterViewport

R3F 캔버스. 배경은 투명이고, 따뜻한 그라데이션의 스테이지 카드 위에 놓인다. 캐릭터는 `Chibi` 컴포넌트 (§8).

- 캐릭터: 머리가 큰 치비. 잉크색 눈 두 개(4초마다 깜빡임) + 짧은 미소
- 회전: 수평 360°만 허용. 줌 없음, 이펙트 때만 살짝 줌인. 좁은 스테이지에서는 폭에 맞춰 물러난다
- idle: 숨쉬기 + 장난감처럼 좌우로 살짝 흔들림
- 재질: 무광 비닐. 파스텔 색 블록(피부·머리·옷), 은은한 광택과 림, 조명은 카메라 기준이라 앞면이 항상 밝다
- 바닥: 둥근 잔디 패치 + 접지 그림자. 빛기둥은 티어/클래스 변경 때만
- 장비 부위: 팔(소매)·손은 뼈 가중치로, 나머지는 발목·허리·목 높이 밴드로 셰이더에서 자른다. 옷단처럼 경계가 깔끔하다. 머리카락과 모자는 머리 슬롯
- 장착된 부위는 색 있는 옷, 빈 부위는 기본 무지 옷(흰 티·베이지 하의·회색 신발)
- 투구는 장착한 채로 캐릭터에서만 숨길 수 있다(장비 카드 머리 칸의 눈 아이콘, `profiles.hide_headwear`). 겉모습이라 공개 값이고, 공개 프로필·마을 캐릭터에도 숨긴 채로 보인다

### 밀도와 기준 화면

웹은 16:9 한 화면(1440×810, 1920×1080)이 기준이다. 페이지는 스크롤되지 않고, 오른쪽 패널만 내용이 넘칠 때 안에서 스크롤된다. 1440×810에서 캐릭터·스탯·장비·클래스·자산이 모두 보여야 한다.
패널을 2열로 펼쳐 카드 높이를 약 550px로 묶었다. 1280×720(1600×900·125%), 1366×768, 1536×864(1080p·125%)까지 스크롤 없이 들어간다. 1700×1000 이상의 큰 화면에서는 패널을 12% 키워 빈 공간을 줄인다(`zoom`).
2열 카드에서 폼은 라벨 왼쪽·입력 오른쪽을 유지하되, 클래스 선택만 라벨 아래로 폼 전체 폭을 쓴다.
모바일은 세로 화면 기준의 일반 스크롤이다.
프로필 편집 폼은 이름 옆 "프로필 편집" 버튼으로 열 때만 펼친다.

### Card

모든 정보 묶음의 기본 틀. 흰 바탕, 24px 반경, 눌리는 그림자, Jua 제목.
등장 시 살짝 튀어 오르고(`pop`) 내용이 뒤따른다. 부트 중에는 열 순서대로 차례차례.

### StatRow

2열 그리드의 작은 타일: 라벨과 자물쇠 / Jua 숫자 + 단위 / 얇은 게이지(리프 그린). 장비·클래스·자산도 같은 타일 리듬을 쓴다.
편집할 때만 타일이 두 칸을 차지한다.

- 값이 바뀌면 숫자가 굴러가고, 옆에 `+0.4kg` 같은 델타가 떠올랐다 사라진다
- **증감 색은 좋음/나쁨으로 판정하지 않고 중립(`--sky`)으로 둔다.** 몸무게 증가가 누군가에겐 목표일 수 있다

### EquipSlot

아이콘만 있는 둥근 타일. 이름(머리·상의·하의·신발)은 hover·포커스 툴팁과 스크린리더로만 보인다. 코드 키는 RPG 의미(helm/armor/greaves/boots)를 유지한다.
4개를 몸 순서(머리 → 신발)대로 한 줄 "장비 레일"에 모은다: 데스크톱은 스테이지 왼쪽 안쪽에 세로로, 모바일은 스테이지 바로 아래 가로로. 오른쪽 장비 카드도 같은 아이콘을 쓴다.

- 빈 슬롯: 점선 + 흐린 실루엣 아이콘
- 채운 슬롯: 레어리티 색 실선 테두리 + 그림자
- hover → 3D 부위 하이라이트(하늘색 림, 나머지 어둡게) + 슬롯과 부위를 잇는 점선. 클릭(본인) → 사이즈 편집 팝오버(장착 / 해제). 모바일에서는 하단 시트

### TierBadge / ClassEmblem

**레어리티 색은 TierBadge와 EquipSlot 테두리에만 허용한다.** TierBadge는 레어리티 색으로 옅게 물든 pill.
클래스에는 레어리티가 없으므로 ClassEmblem은 리프 그린 원 위의 선 글리프(육각 프레임 + 직업 상징).

### VisibilityToggle

모든 필드 옆에 붙는 둥근 자물쇠 칩. 이 서비스에서 가장 중요한 컴포넌트.

- 공개: 리프 그린 바탕 + 열린 자물쇠 / 비공개: 연회색 바탕 + 잠긴 자물쇠
- 비공개 전환 시 값이 꾹 눌렸다가 서리 유리처럼 흐려진다
- **"타인에게 보이는 화면 미리보기" 버튼을 반드시 함께 둔다**

### PanelForm (본인 뷰 입력)

기본 스탯·장비·클래스는 카드 단위로 한 번에 입력한다 (`PanelForms.tsx`).
카드 제목 옆 "입력" 버튼이나 타일을 누르면 그 카드가 제자리에서 폼으로 바뀌고, 누른 타일의 필드에 포커스가 간다.

- 한 폼에 그 카드의 모든 필드가 있다. Tab으로 이동, Enter·저장으로 저장, Esc·취소로 닫는다. 바뀐 필드만 저장해서 바뀐 것마다 이펙트가 한 번씩 난다
- 숫자는 단위가 안에 붙은 입력칸 (`UnitInput`), ↑↓로 조절
- 사이즈는 자주 쓰는 값을 칩으로 고르고 (다시 누르면 해제), 그 밖의 값은 "직접" 칸에 쓴다 (`ChoiceChips`)
- 클래스는 엠블럼 버튼 7개 중 하나를 고른다. 고르면 해당 직업군과 컨셉이 아래에 뜬다
- 장비 레일 팝오버도 같은 필드 컴포넌트(`SlotFields`)를 쓴다
- 닉네임·핸들·체형·헤어는 "프로필 편집"에 남는다

### Modal

모든 모달은 `Modal`(`src/components/Modal.tsx`) 하나로 띄운다. 페이지를 떠나지 않고 잠깐 보거나 확인하는 자리다.

- 형태: 흰 카드(24px 반경, `--lift-hover`)가 코코아색 22% 어둠 위에 뜬다. 폭은 sm 400 · md 480 · lg 640px. 휴대폰(≤560px)에서는 아래에서 올라오는 시트(위 모서리만 둥글게, 손잡이 바)
- 구성: 머리(Jua 18px 제목 + 36px 닫기 ×) / 내용(이 부분만 스크롤) / 필요하면 아래 행동 줄(점선 구분, 오른쪽 정렬, 주 버튼이 맨 오른쪽)
- 닫기: ×, 바깥 누르기, Esc. 열면 내용의 첫 입력칸이나 버튼에 포커스가 가고, 열려 있는 동안 Tab은 모달 안에서만 돈다. 닫으면 연 버튼으로 포커스가 돌아온다. 뒤 페이지는 스크롤되지 않는다
- 등장: `pop`(살짝 지나쳤다 자리 잡기), 시트는 아래에서 미끄러져 올라온다. 줄인 모션 설정이면 페이드만
- 되돌릴 수 없는 일(탈퇴)은 확인 문구를 직접 입력해야 주 버튼이 열린다
- 쓰는 곳: 설정(`SettingsModal`: 공개 설정 · 계정/로그아웃 · 위험 구역), 아이템 편집(`/me/items`), 공개 프로필 요약(`ProfileModal`, 마을)

### ProfileModal

마을에서 다른 사람의 공개 프로필을 요약해서 보여주는 sm 모달. 3D 무대 없이 Lv·칭호·핸들, 클래스·직업, 자산 티어, 공개한 스탯, 장비 4칸, 진열장만 담는다. 행동은 "옆으로 가기" · "말 걸기" · "전체 프로필"(`/p?u=`). 공개 프로필 페이지에도 상단 바가 있어서 전체 프로필로 가도 메뉴로 돌아올 수 있다.

### Inventory (`/me/items`)

아이콘 위주, 텍스트는 작게.

- 위: 제목·개수, 검색, "추가". 그 아래 분류 아이콘 칩(아이콘 + 11px 이름 + 개수, 가로 스크롤), "다시 살 것"·"보충 필요" 필터
- 아이템 타일: 분류 아이콘 큰 칸 + 이름 12px 한 줄 + 브랜드·N년차 11px. 오른쪽 위에 진열(트로피)·보충·재구매 배지
- 타일을 누르면 `ItemForm`이 가운데 카드(모바일은 하단 시트)로 열린다. 이름만 있어도 저장되고 나머지는 나중에 채운다
- 추가는 연속 입력: 이름·브랜드·분류만 보이고, 모델명·구매·평가·진열장은 "더 적기"로 접혀 있다(접어도 입력한 값은 저장된다). Enter나 "추가"는 저장 후 폼을 비우고 이름 칸으로 돌아가며, 이번에 추가한 이름이 아래에 쌓인다. "완료"는 적던 것을 저장하고 닫는다
- 분류는 손으로 고르기 전까지 이름에서 자동으로 고른다(`guessCategory`: 분류 힌트 + 브랜드·일상어 키워드). 손으로 고른 분류는 다음 아이템에도 유지된다
- 수정할 때는 모든 칸이 펼쳐져 있고 버튼은 삭제·취소·저장
- 아이콘은 `ItemIcon`(SlotIcon과 같은 24px 선 아이콘). 이모지는 쓰지 않는다

### TrophyShelf

공개 프로필과 `/me` 패널 맨 아래의 진열장 카드. 3×2 받침대에 분류 아이콘(선 옐로 원) + 이름 + 브랜드·연도.
본인 뷰는 빈 칸을 점선으로 보여주고 인벤토리로 가는 링크를 단다. 타인 뷰는 진열한 게 없으면 카드를 숨긴다.

## 8. 3D 캐릭터 생성

리깅된 치비 베이스 메쉬 하나를 옷 입히고 체형에 맞게 늘린다 (`src/lib/chibiRig.ts`, `src/components/Chibi.tsx`).

- 모델: "Free Pack - Chibi Base Mesh (Rigged)" (DuNguyn Studio, CC-BY-4.0, `public/models/chibi`). 정점 1.2천 개, Mixamo식 뼈대, 텍스처 없음. 크레딧은 README
- 불러올 때 T자 팔을 내리고, 키 0.8(월드 단위)·발바닥 y = 0으로 맞춘다
- 색 구역: 정점마다 가장 큰 뼈 가중치로 팔·손·머리 마스크를 싣고, 나머지는 bind 공간 높이 밴드(발목·허리·목)로 나눈다. 애니메이션이 붙어도 옷단이 몸을 따라간다
- 체형은 뼈 크기 조절이다. 각 뼈에 절대 [길이, 둘레] 배율을 주고, 자식에는 부모 배율로 나눈 값을 넣어 상속을 상쇄한다. 키는 다리·몸통 길이, 몸무게는 골반·몸통·다리 둘레, 근육은 팔·가슴, 체형(성별)은 골반·허리. 다리가 길어지면 발 위치로 다시 바닥에 세운다
- 헤어 5종·모자·입은 머리 뼈에 붙인 기본 도형이다(bind 공간에서 만들어 `boneInverse × bindMatrix`로 옮긴다). 헤어는 공개 범위와 상관없이 항상 보인다
- 머리 장비는 종류별 등록표 `HEADWEAR`(`src/components/Headwear.tsx`)로 그린다. 종류를 늘리면 항목 하나를 더한다. 각 항목은 두개골 중심·반지름으로 모양을 만들고, 가리는 머리 부분(`bun` 똥머리, `knot` 포니테일 묶음)을 적는다. 모양은 가장 넓은 헤어(단발) 바깥에 있어야 한다. 종류: 캡(기본)·비니(접힌 단, 방울)·버킷햇(둘레 전체가 내려가는 챙). 종류 값은 `profiles.gear.head`, 라벨은 `src/lib/gear.ts`
- 모자(`cap`): 두개골 구면 위의 캡(0.49π, 뒤로 0.13 기울임)이라 테두리가 앞은 눈썹 위, 뒤는 귀 위를 지난다. 테두리 밴드, 꼭지 단추, 반원 챙(눈 위로 살짝 숙임). 모자를 쓰면 똥머리는 숨고 포니테일은 테두리 아래에서 나온다
- 모든 재질은 같은 조명 함수와 `TOY_TINT`(마을의 시간대 색조)를 쓴다

- 이전 안: SDF + surface nets로 브라우저에서 만든 절차적 SD 몸(`bodyMesh.ts`, git 기록에 있음). 체형 변화 폭은 컸지만 뼈대가 없어 걷기 같은 애니메이션을 붙일 수 없었다
- 그 전 안: MakeHuman CC0 실사 체형. 실루엣이 웹 한 화면에 잘 맞지 않았다
- 걷기: 허벅지가 서로 반대로 흔들리고 뒤로 간 다리의 무릎이 굽고, 팔은 다리와 반대로 흔든다. 한 걸음마다 몸이 살짝 튄다(`poseWalk`, 마을 전용). 멈추면 서서히 선 자세로 돌아온다
- 다음 단계: 상의·하의·신발의 형태 변화

## 9. 마을

동물의 숲 주민 지도처럼 다른 플레이어를 만나는 작은 공간 (`/village`). 저사양 우선.

- **맵**: 책 디오라마. "Medieval Fantasy Book" (Pixel, CC-BY-4.0), 약 5.5만 면, 풍차·물레방아 애니메이션 포함 (`src/components/village/BookVillage.tsx`)
  - 이전 안: 아주 작은 행성 같은 구체 공원
- **사람**: 접속 중인 플레이어만 치비로 보인다. 머리 위에 직업 엠블럼 + 닉네임(내 이름표는 리프 그린)
- **조작**: 우클릭은 이동, 좌클릭은 상호작용이 기본이다. 좌클릭 드래그만으로는 카메라가 돌지 않는다
  - 책 위 평평한 땅을 우클릭하면 그 자리로 걸어간다. 찍은 자리에 하늘색 물결이 한 번 퍼지고, 도착(또는 멈춤)할 때까지 작은 고리가 숨 쉬듯 남는다. 걷는 중에 다시 우클릭하면 그쪽으로 바로 방향을 튼다. 터치에는 우클릭이 없어서 탭으로 걷는다
  - 내 캐릭터나 내 이름표를 0.35초 꾹 누르면 집어 든다(캐릭터가 작아서 이름표가 잡기 쉽다). 커서를 따라 공중에서 다리를 흔들고, 떨어질 자리에 고리가 보인다. 놓으면 그 자리에 떨어져 착지할 때 살짝 찌그러진다. 맵 밖에서 놓으면 가장 가까운 맵 가장자리 안쪽으로 간다. 0.35초가 되기 전에 움직이면 집지 않는다
  - 다른 사람(캐릭터나 이름표)에 커서를 올리면 이름표에 하늘색 테가 생긴다. 좌클릭하면 채팅 입력칸에 `@닉네임`이 들어가고, 우클릭하면 커서 자리에 메뉴(말 걸기 · 옆으로 가기 · 프로필 보기)가 뜬다. 메뉴는 바깥을 누르거나 Esc로 닫는다. "프로필 보기"는 `ProfileModal`을 띄워 마을을 떠나지 않는다
  - Space를 누르고 있는 동안 마우스로 시점을 바꾼다(드래그 회전). 휠 확대·축소는 언제나 된다. 휴대폰은 Space가 없으니 두 손가락으로 돌리고 오므려 확대하고, 한 손가락은 탭(이동·멘션)에 남긴다. 채팅 입력 중이나 모달 안에서는 Space가 시점에 쓰이지 않는다
- **걷기와 지형** (`src/components/village/physics.ts`): 최소한의 물리만 둔다. 맵 메시에 BVH(`three-mesh-bvh`)를 만들어 광선을 싸게 쏜다
  - 캐릭터는 책 폭의 약 1/70 크기(`FIGURE_SCALE` 0.07)다. 발은 땅을 따라가고, 키의 약 1/3(월드 0.022) 이하의 턱은 그냥 올라선다
  - 내리막과 내려가는 턱(턱 높이의 1.5배까지)은 발을 땅에 붙인 채 걸어 내려간다. 그보다 깊은 낭떠러지에서만 떨어진다
  - 벽은 턱 높이에서 쏜 광선으로만 느낀다(그보다 낮은 건 벽이 아니다). 법선 y < 0.6인 면이 벽이다. 막히면 벽을 따라 미끄러지고, 그래도 막히면 좌우로 30°·60°·85° 틀어 돌아간다. 1.5초 동안 목표에 더 가까워지지 못하면 거기서 멈춘다. 책 바깥으로는 걸어 나가지 않는다
  - 공중에 있으면 중력으로 떨어진다(지붕에서 걸어 나가거나 들어서 떨어뜨렸을 때)
  - 일정한 속도로 그쪽을 보고 통통 튀며 걷는다. 시뮬레이션은 각자 화면에서 돌리고, 내 캐릭터가 목표보다 앞에서 멈추면 실제로 선 자리를 다시 알려서 다른 사람 화면과 맞춘다
- **채팅**: 말풍선만. 60자, 6초 뒤 사라지고 저장하지 않는다. 지금 마을에 있는 사람의 `@닉네임`은 하늘색, 나를 부른 멘션은 선 옐로 바탕으로 칠한다
- **멘션 알림**: 누가 내 `@닉네임`을 부르면 지도 위쪽에 알림 카드(선 옐로 종 + 누가 + 한 말 + "답하기")가 8초 동안 뜬다. 최대 3장. 탭을 보고 있지 않으면 탭 제목에 `(n) 누가 불렀어요`가 붙고, 돌아오면 지운다. "답하기"는 그 사람의 `@닉네임`을 입력칸에 넣는다
- **하늘**: 한국 시간(KST)에 맞춰 하늘색·조명이 바뀐다 (`src/lib/daylight.ts`, 1분마다 확인). 캐릭터 재질도 같은 색조(`TOY_TINT`)를 받는다
- **카메라** (`CameraRig`): 두 모드를 Y(또는 지도 왼쪽 아래 버튼, 휴대폰은 오른쪽 위)로 바꾼다. 모드가 바뀔 때는 날아가듯 옮겨 간다
  - **따라가기**(기본): 쿼터뷰 각도로 약 0.6 떨어져 내 캐릭터를 부드럽게 따라간다. 돌리고 확대한 각도·거리는 유지되고, 전경에 다녀와도 그대로다. 캐릭터를 들고 있는 동안은 멈춘다(놓을 자리를 이 카메라로 읽기 때문)
  - **전경**: 책 전체를 내려다본다(예전의 첫 화면). 좁은 화면에서는 물러나 책 전체가 들어온다
  - 캐릭터와 카메라 사이에 지붕·벽이 있으면 카메라를 그 앞으로 당겨 그린다. 그리기에만 적용하고 다음 프레임에 되돌려서, 정한 거리가 줄어들지 않는다

### 실시간과 프라이버시

- Supabase Realtime 비공개 채널 하나(topic `village`, `src/lib/useVillage.ts`). RLS로 로그인한 사용자만 듣고 보낼 수 있다 (`supabase/migrations/20261003040000_village_realtime.sql`)
- presence: 탭마다 하나의 키. 실은 값은 핸들·닉네임·클래스·체형·장비 착용 여부·위치(책 위 비율)·`warp`(들어서 옮긴 횟수: 바뀌면 걸어오지 않고 그 자리에 떨어진다)뿐이고, 모두 `get_public_profile` 결과로 만든다. **비공개 필드는 마을로 나가지 않는다**(비공개 체형은 평균 체형)
- 다른 사람이 탭을 여러 개 열어도 한 명으로 보인다(핸들로 묶음). 나가면 바로, 창을 닫으면 몇 초 안에 사라진다
- broadcast `say`: 말풍선. 서버에 남지 않는다
- 같은 이름의 채널을 다시 열 때는 이전 채널 정리가 끝난 뒤에 연다(클라이언트가 정리 중인 채널을 돌려주는 문제)
- 첫 등장: 무작위 지점에서 가장 가까운 트인 평지로 내려온다(`openGroundNear`: 평평하고, 둘레가 고르고, 마을 지면 높이의 중앙값 근처. 강·지붕·물레방아·나무 위는 제외). 들어서 놓은 것처럼 떨어진다
- 연결이 끊기면(탭이 잠들거나 네트워크) 3초 뒤 다시 들어오고, 탭을 다시 보면 바로 들어온다. 하트비트는 Web Worker에서 돈다(`realtime.worker`)

## 10. 계획: 장비 종류 확장

1단계(머리 종류)까지 구현했다. 나머지는 계획이다. 지금은 슬롯 4개(머리·상의·하의·신발)에 사이즈가 있고, 모양은 머리 슬롯에만 종류(캡·비니·버킷햇)가 있다.

### 목표

- 슬롯마다 "무엇을 입었는지"(종류)를 고른다. 사이즈 기록은 그대로 둔다
- 종류는 캐릭터 모양에 반영된다. 저폴리 기본 도형과 셰이더 색 구역으로 만든다
- 나중에는 인벤토리 아이템(가방·시계·안경 등)을 장비로 착용한다

### 종류 후보

| 슬롯 | 종류 | 표현 |
|---|---|---|
| 머리 | 캡(지금), 비니, 버킷햇, 헬멧 | `HEADWEAR` 항목. 머리 뼈에 붙인 도형 |
| 상의 | 반팔, 긴팔, 후디, 재킷 | 소매 길이는 셰이더 경계(팔 마스크를 뼈 축 따라 자름), 후드·옷깃은 도형 |
| 하의 | 반바지, 긴바지, 치마 | 기장은 높이 밴드, 치마는 골반 뼈에 붙인 원뿔 |
| 신발 | 운동화, 부츠, 샌들 | 발목 밴드 높이 + 발 뼈에 붙인 도형 |
| (새 슬롯) 얼굴 | 안경, 선글라스 | 머리 뼈, 눈 위치 기준 |
| (새 슬롯) 등 | 백팩 | 가슴 뼈(Spine2) |
| (새 슬롯) 손목 | 시계 | 아래팔 뼈 끝 |

### 데이터

- `profiles`에 `gear jsonb` 하나를 둔다. 예: `{"head": "beanie", "top": "hoodie"}`
  - 종류가 늘 때마다 마이그레이션하지 않도록 jsonb로 두고, 허용 값은 앱의 등록표가 정한다. DB는 키(슬롯 이름)만 검사한다
  - 사이즈 컬럼(`hat_size` 등)은 그대로 쓴다. 종류가 없고 사이즈만 있으면 슬롯의 기본 종류로 본다(머리 = 캡)
- 공개 범위: 장비의 겉모습(종류)은 지금의 "슬롯 외형 공개"처럼 공개, 사이즈는 슬롯별 공개 설정을 따른다. `get_public_profile`의 `equipment`에 `kind`를 더한다
- 새 슬롯을 열면 `visibility` 키와 `EQUIP_SLOTS`, 장비 레일 아이콘이 함께 늘어난다

### 코드 구조

- 슬롯마다 등록표 하나: `HEADWEAR`(있음), `TOPWEAR`, `BOTTOMWEAR`, `FOOTWEAR` …
  - 항목 = 라벨, 렌더 함수(뼈 기준 도형), 셰이더 값(소매·기장), 가리는 부위(`hides`)
- 셰이더 `uBands`·팔 마스크를 종류별 값으로 받아 소매·기장을 바꾼다
- 입력: 장비 카드 폼과 슬롯 팝오버에 종류 칩을 더한다(사이즈 칩과 같은 `ChoiceChips` 형식)
- 이펙트: 종류가 바뀌어도 지금의 장착 반짝임을 쓴다

### 단계

1. ~~`gear` 필드 + 머리 종류 3개(캡·비니·버킷햇) + 종류 칩 입력~~ (완료: `profiles.gear`, `src/lib/gear.ts`, 장비 폼·팝오버의 "종류" 칩, 종류가 바뀌면 장착 반짝임)
2. 상의 소매 길이·하의 기장(셰이더만, 도형 없음)
3. 후디·치마·부츠처럼 도형이 필요한 종류
4. 새 슬롯(얼굴·등·손목)과 장비 레일 확장
5. 인벤토리 연결: 가방·잡화·디지털 아이템을 해당 슬롯 장비로 착용, 진열장과 함께 공개 여부 선택
