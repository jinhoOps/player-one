## 1. 정보 구조

핵심 아이디어: **의상 사이즈를 장비 슬롯에 붙인다.** 사이즈는 따로 노는 표가 아니라 "이 슬롯에 맞는 장비 규격"이다.

| 섹션 | 항목 | 게임식 표현 | 기본 공개 범위 |
|---|---|---|---|
| 프로필 | 닉네임, 칭호, 만 나이 | 캐릭터명 / Title / Lv. | 공개 |
| 클래스 | 직업군 + 실제 직업명 | Class / Subclass | 클래스 공개, 직업명 비공개 |
| 체형 | 성별 체형 (여성/남성) | 캐릭터 실루엣 | 비공개 |
| 외형 | 헤어스타일 (숏컷·단발·긴 머리·포니테일·똥머리) | 캐릭터 외형 | 항상 공개 |
| 신체 | 키, 몸무게, 골격근량, (체지방률) | Base Stats | 비공개 |
| 장비 | 투구 = 머리둘레/모자, 상의 = 상의 사이즈, 하의 = 허리둘레·하의 사이즈, 신발 = mm | Equipment Slots | 슬롯 외형 공개, 수치 비공개 |
| 자산 | 구간 | Wealth Tier | 비공개 |
| 인벤토리 | 오래 쓰려고 산 물건 (모델명·구매일·가격·구매처·수량·다시 살까·후기) | Inventory / 진열장 | 비공개, 진열한 것만 공개 |

### 클래스 매핑

| 클래스 | 직업군 | 컨셉 |
|---|---|---|
| 전사 | 현장·제조·운동·영업 | 몸으로 돌파 |
| 마법사 | 개발·연구·데이터 | 지식으로 세계를 조작 |
| 탱커 | 공공·관리·CS·운영 | 버티고 지킴 |
| 힐러 | 의료·돌봄·교육 | 남을 회복시킴 |
| 레인저 | 디자인·기획·마케팅 | 원거리 정밀 타격 |
| 상인 | 자영업·금융·사업 | 자원 순환 |
| 음유시인 | 크리에이터·예술 | 버프와 영향력 |

### 인벤토리

오래 쓰려고 산 물건을 기록해 두고, 나중에 찾아보고, 다시 사거나 수량을 채울 때 본다. 옷은 성격이 달라서 따로 "옷장"으로 설계한다(보류).

| 대분류 | 키 | 예시 |
|---|---|---|
| 디지털 | `digital` | 노트북·태블릿·폰·모니터·키보드·마우스·이어폰·충전기 |
| 카메라 | `camera` | 바디·렌즈·삼각대·액션캠·드론·조명 |
| 가방·잡화 | `bag` | 백팩·토트·지갑·시계·안경·벨트·우산·부티크 |
| 주방 | `kitchen` | 팬·웍·냄비·칼·도마·식기·텀블러·주방가전 |
| 리빙·가전 | `living` | 청소기·공기청정기·가습기·조명·침구·수건·가구 |
| 취미·레저 | `hobby` | 게임기·악기·캠핑·자전거·운동기구·피규어·문구 |
| 뷰티·케어 | `care` | 드라이기·면도기·향수·전동칫솔 |
| 직접 | `custom` | 이름을 직접 붙인 분류. 이름은 나만 본다 |

- 다시 사기에 필요한 것 위주: 모델명(품번), 구매처 링크, "다시 살까"(같은 걸로 / 다른 걸로 / 안 삼), 한 줄 후기
- 수량형: 수건·식기처럼 개수를 채워 두는 물건만 보유/적정 수량을 적는다. 보유 < 적정이면 "보충" 배지
- 처분한 물건도 지우지 않고 흐리게 남긴다(다음 구매 때 참고)

### 자산 티어

- 1억 미만: 천만 원 단위 10구간
- 1억 이상: 억 단위 구간
- **정확한 금액은 저장하지 않고 구간 인덱스만 저장한다.** 유출 시 피해를 최소화하기 위함.

| 레어리티 | 구간 |
|---|---|
| Common | 3천만 원 미만 |
| Uncommon | 3천만 ~ 1억 |
| Rare | 1억 ~ 5억 |
| Epic | 5억 ~ 10억 |
| Legendary | 10억 이상 |

## 2. 프라이버시 모델

### 필드 단위 공개 설정

Supabase RLS는 행 단위라 필드별 공개 설정을 직접 걸 수 없다.

- 모든 프로필 데이터는 **본인만 읽을 수 있는 테이블**에 둔다 (RLS: `auth.uid() = user_id`).
- 같은 행에 필드별 공개 여부 맵 `visibility jsonb`를 저장한다.
- 타인 조회는 `get_public_profile(handle)` — `SECURITY DEFINER` RPC가 `visibility`를 보고 공개 필드만 골라 반환한다. 테이블 자체는 anon에 노출하지 않는다.

### 핸들

- 핸들이 없으면 `/me` 이름 카드 아래 "공개 주소 정하기" 카드(`HandleClaim`)가 뜬다. 로그인 계정 아이디(이메일 앞부분)를 핸들 규칙에 맞춰 미리 채우고, 이미 쓰는 이름이면 `_2`, `_3`…을 붙인다.
- 구글 계정 아이디는 곧 이메일 주소라서 자동으로 공개하지 않는다. 본인이 "이 주소로 공개"를 눌러야 저장되고, 계정 아이디 그대로면 그 점을 알려준다.

### 3D 모델을 통한 누설

몸무게·골격근량으로 체형 morph를 만들면, 수치를 가려도 실루엣으로 드러난다.

- 신체 스탯이 비공개면 **타인 뷰에서는 해당 축이 평균 체형**으로 나온다. 체형(성별)이 비공개면 중성 마네킹이다.
- 비공개 값은 RPC 응답 단계에서 이미 빠져 있다. 클라이언트는 받은 공개 값으로만 morph를 계산하므로 비공개 morph 파라미터가 섞일 수 없다.
- morph 축(`src/lib/morph.ts`)은 한국 20–30대 평균 대비 −1…1이다. 키는 cm, 몸무게는 BMI, 골격근량은 체중 대비 비율로 본다.
- 헤어스타일은 외형이라 항상 공개한다. 비워 두면 체형별 기본값(여성 단발, 그 외 숏컷)을 쓴다.

### 인벤토리와 진열장

- `items`도 본인만 읽고 쓰는 테이블이다. 모든 아이템은 기본 비공개다.
- 아이템마다 "진열"을 켤 수 있고, 진열장은 6칸이다(DB 트리거로도 막는다).
- 타인은 `get_public_trophies(handle)`로 진열한 아이템의 **분류·이름·브랜드·구매 연도만** 받는다. 가격·구매처·모델명·후기·수량은 진열해도 나가지 않는다.
- 직접 만든 분류는 이름 없이 `custom`으로만 나간다.

## 3. 라우팅과 인증

| 경로 | 내용 |
|---|---|
| `/` | 랜딩: 큰 워드마크(Player One) + 캐릭터 미리보기 + Google 로그인 + 특징 카드 3개 |
| `/me` | 내 캐릭터 시트, 인라인 편집, 진열장 미리보기 |
| `/me/items` | 인벤토리: 아이콘 그리드, 분류·검색·필터, 아이템 편집 |
| `/p?u=<handle>` | 공개 뷰 + 진열장 |
| `/village` | 마을: 접속 중인 플레이어, 말풍선 채팅 (핸들 필요) |
| `/settings` | 공개 범위 일괄 관리 |

- 정적 export(`output: 'export'`)에서는 `/p/[handle]` 같은 동적 경로를 빌드 시점에 만들 수 없다. 공개 프로필은 `/p?u=handle` 형태로 **클라이언트에서 fetch**한다.
- Google 로그인은 PKCE 콜백 페이지를 클라이언트에서 처리한다.

## 4. 레이아웃

### 데스크톱

16:9 한 화면 구도.

- 왼쪽: 3D 스테이지 (넓게). 왼쪽 안쪽에 장비 레일(아이콘 4개, 머리 → 신발)
- 오른쪽: 정보 패널 (360–440px, 넘치면 패널 안에서만 스크롤)
- 슬롯 hover → 3D 모델의 해당 부위가 빛나고, 슬롯과 부위 사이에 점선이 그려진다

### 모바일

- 상단: 화면 폭 3D 스테이지(52vh), 그 아래 장비 슬롯 4개가 한 줄
- 하단: 탭 (스탯 / 장비 / 클래스·자산). 장비 팝오버는 하단 시트
- 아래로 스크롤하면 위에 고정된 스테이지가 52vh → 28vh로 줄어들며 패널이 올라온다

### 공통

- 캐릭터와 슬롯 열은 한 화면 높이로 고정(sticky)되어, 오른쪽 패널을 스크롤해도 캐릭터 전체가 보인다.

## 6. 컴포넌트

### CharacterViewport

R3F 캔버스. 배경은 투명이고, 따뜻한 그라데이션의 스테이지 카드 위에 놓인다. 캐릭터는 `Chibi` 컴포넌트 (§8).

- 캐릭터: 머리가 큰 치비. 잉크색 눈 두 개(4초마다 깜빡임) + 짧은 미소
- 회전: 수평 360°만 허용. 줌 없음, 이펙트 때만 살짝 줌인. 좁은 스테이지에서는 폭에 맞춰 물러난다
- idle: 숨쉬기 + 장난감처럼 좌우로 살짝 흔들림
- 재질: 무광 비닐. 파스텔 색 블록(피부·머리·옷), 은은한 광택과 림, 조명은 카메라 기준이라 앞면이 항상 밝다
- 바닥: 둥근 잔디 패치 + 접지 그림자. 빛기둥은 티어/클래스 변경 때만
- 장비 부위: 팔(소매)·손은 뼈 가중치로, 나머지는 발목·허리·목 높이 밴드로 셰이더에서 자른다. 옷단처럼 경계가 깔끔하다. 머리카락과 모자는 머리 슬롯
- 장착된 부위는 색 있는 옷, 빈 부위는 기본 무지 옷(흰 티·베이지 하의·회색 신발)

### 밀도와 기준 화면

웹은 16:9 한 화면(1440×810, 1920×1080)이 기준이다. 페이지는 스크롤되지 않고, 오른쪽 패널만 내용이 넘칠 때 안에서 스크롤된다. 1440×810에서 캐릭터·스탯·장비·클래스·자산이 모두 보여야 한다.
모바일은 세로 화면 기준의 일반 스크롤이다.
프로필 편집 폼은 이름 옆 "프로필 편집" 버튼으로 열 때만 펼친다.

### Card

모든 정보 묶음의 기본 틀. 흰 바탕, 24px 반경, 눌리는 그림자, Jua 제목.
등장 시 살짝 튀어 오르고(`pop`) 내용이 뒤따른다. 부트 중에는 열 순서대로 차례차례.

### StatRow

2열 그리드의 작은 타일: 라벨과 자물쇠 / Jua 숫자 + 단위 / 얇은 게이지(리프 그린). 장비·클래스·자산도 같은 타일 리듬을 쓴다.
편집할 때만 타일이 두 칸을 차지한다.

- 값이 바뀌면 숫자가 굴러가고, 옆에 `+0.4kg` 같은 델타가 떠올랐다 사라진다
- **증감 색은 좋음/나쁨으로 판정하지 않고 중립(`--sky`)으로 둔다.** 몸무게 증가가 누군가에겐 목표일 수 있다

### EquipSlot

아이콘만 있는 둥근 타일. 이름(머리·상의·하의·신발)은 hover·포커스 툴팁과 스크린리더로만 보인다. 코드 키는 RPG 의미(helm/armor/greaves/boots)를 유지한다.
4개를 몸 순서(머리 → 신발)대로 한 줄 "장비 레일"에 모은다: 데스크톱은 스테이지 왼쪽 안쪽에 세로로, 모바일은 스테이지 바로 아래 가로로. 오른쪽 장비 카드도 같은 아이콘을 쓴다.

- 빈 슬롯: 점선 + 흐린 실루엣 아이콘
- 채운 슬롯: 레어리티 색 실선 테두리 + 그림자
- hover → 3D 부위 하이라이트(하늘색 림, 나머지 어둡게) + 슬롯과 부위를 잇는 점선. 클릭(본인) → 사이즈 편집 팝오버(장착 / 해제). 모바일에서는 하단 시트

### TierBadge / ClassEmblem

**레어리티 색은 TierBadge와 EquipSlot 테두리에만 허용한다.** TierBadge는 레어리티 색으로 옅게 물든 pill.
클래스에는 레어리티가 없으므로 ClassEmblem은 리프 그린 원 위의 선 글리프(육각 프레임 + 직업 상징).

### VisibilityToggle

모든 필드 옆에 붙는 둥근 자물쇠 칩. 이 서비스에서 가장 중요한 컴포넌트.

- 공개: 리프 그린 바탕 + 열린 자물쇠 / 비공개: 연회색 바탕 + 잠긴 자물쇠
- 비공개 전환 시 값이 꾹 눌렸다가 서리 유리처럼 흐려진다
- **"타인에게 보이는 화면 미리보기" 버튼을 반드시 함께 둔다**

### PanelForm (본인 뷰 입력)

기본 스탯·장비·클래스는 카드 단위로 한 번에 입력한다 (`PanelForms.tsx`).
카드 제목 옆 "입력" 버튼이나 타일을 누르면 그 카드가 제자리에서 폼으로 바뀌고, 누른 타일의 필드에 포커스가 간다.

- 한 폼에 그 카드의 모든 필드가 있다. Tab으로 이동, Enter·저장으로 저장, Esc·취소로 닫는다. 바뀐 필드만 저장해서 바뀐 것마다 이펙트가 한 번씩 난다
- 숫자는 단위가 안에 붙은 입력칸 (`UnitInput`), ↑↓로 조절
- 사이즈는 자주 쓰는 값을 칩으로 고르고 (다시 누르면 해제), 그 밖의 값은 "직접" 칸에 쓴다 (`ChoiceChips`)
- 클래스는 엠블럼 버튼 7개 중 하나를 고른다. 고르면 해당 직업군과 컨셉이 아래에 뜬다
- 장비 레일 팝오버도 같은 필드 컴포넌트(`SlotFields`)를 쓴다

### Inventory (`/me/items`)

아이콘 위주, 텍스트는 작게.

- 위: 제목·개수, 검색, "추가". 그 아래 분류 아이콘 칩(아이콘 + 11px 이름 + 개수, 가로 스크롤), "다시 살 것"·"보충 필요" 필터
- 아이템 타일: 분류 아이콘 큰 칸 + 이름 12px 한 줄 + 브랜드·N년차 11px. 오른쪽 위에 진열(트로피)·보충·재구매 배지
- 타일을 누르면 `ItemForm`이 가운데 카드(모바일은 하단 시트)로 열린다. 이름만 있어도 저장되고 나머지는 나중에 채운다
- 아이콘은 `ItemIcon`(SlotIcon과 같은 24px 선 아이콘). 이모지는 쓰지 않는다

### TrophyShelf

공개 프로필과 `/me` 패널 맨 아래의 진열장 카드. 3×2 받침대에 분류 아이콘(선 옐로 원) + 이름 + 브랜드·연도.
본인 뷰는 빈 칸을 점선으로 보여주고 인벤토리로 가는 링크를 단다. 타인 뷰는 진열한 게 없으면 카드를 숨긴다.

## 8. 3D 캐릭터 생성

리깅된 치비 베이스 메쉬 하나를 옷 입히고 체형에 맞게 늘린다 (`src/lib/chibiRig.ts`, `src/components/Chibi.tsx`).

- 모델: "Free Pack - Chibi Base Mesh (Rigged)" (DuNguyn Studio, CC-BY-4.0, `public/models/chibi`). 정점 1.2천 개, Mixamo식 뼈대, 텍스처 없음. 크레딧은 README
- 불러올 때 T자 팔을 내리고, 키 0.8(월드 단위)·발바닥 y = 0으로 맞춘다
- 색 구역: 정점마다 가장 큰 뼈 가중치로 팔·손·머리 마스크를 싣고, 나머지는 bind 공간 높이 밴드(발목·허리·목)로 나눈다. 애니메이션이 붙어도 옷단이 몸을 따라간다
- 체형은 뼈 크기 조절이다. 각 뼈에 절대 [길이, 둘레] 배율을 주고, 자식에는 부모 배율로 나눈 값을 넣어 상속을 상쇄한다. 키는 다리·몸통 길이, 몸무게는 골반·몸통·다리 둘레, 근육은 팔·가슴, 체형(성별)은 골반·허리. 다리가 길어지면 발 위치로 다시 바닥에 세운다
- 헤어 5종·모자·입은 머리 뼈에 붙인 기본 도형이다(bind 공간에서 만들어 `boneInverse × bindMatrix`로 옮긴다). 헤어는 공개 범위와 상관없이 항상 보인다
- 모든 재질은 같은 조명 함수와 `TOY_TINT`(마을의 시간대 색조)를 쓴다

- 이전 안: SDF + surface nets로 브라우저에서 만든 절차적 SD 몸(`bodyMesh.ts`, git 기록에 있음). 체형 변화 폭은 컸지만 뼈대가 없어 걷기 같은 애니메이션을 붙일 수 없었다
- 그 전 안: MakeHuman CC0 실사 체형. 실루엣이 웹 한 화면에 잘 맞지 않았다
- 다음 단계: 상의·하의·신발의 형태 변화, 마을용 걷기 애니메이션

## 9. 마을

동물의 숲 주민 지도처럼 다른 플레이어를 만나는 작은 공간 (`/village`). 저사양 우선.

- **맵**: 책 디오라마. "Medieval Fantasy Book" (Pixel, CC-BY-4.0), 약 5.5만 면, 풍차·물레방아 애니메이션 포함 (`src/components/village/BookVillage.tsx`)
  - 이전 안: 아주 작은 행성 같은 구체 공원
- **사람**: 접속 중인 플레이어만 치비로 보인다. 머리 위에 직업 엠블럼 + 닉네임(내 이름표는 리프 그린). 이름표를 누르면 그 사람의 공개 프로필
- **걷기**: 책 위 평평한 땅을 누르면(드래그는 회전) 그 자리로 걸어간다. 일정한 속도로 그쪽을 보고 통통 튀며 걷는다. 서 있는 높이는 위에서 쏜 광선이 책 표면에 닿는 곳
- **채팅**: 말풍선만. 60자, 6초 뒤 사라지고 저장하지 않는다
- **하늘**: 한국 시간(KST)에 맞춰 하늘색·조명이 바뀐다 (`src/lib/daylight.ts`, 1분마다 확인). 캐릭터 재질도 같은 색조(`TOY_TINT`)를 받는다
- 좁은 화면에서는 카메라가 물러나 책 전체가 보인다

### 실시간과 프라이버시
